# Fairflow — документация backend

Fairflow — проектно-центричная модульная CRM-платформа. Этот каталог описывает,
как устроена серверная часть: из чего она собрана, как сервисы разговаривают
между собой и как устроен доступ.

## Понять систему за 10 минут

1. **Один вход.** Клиент ходит только в gateway (HTTP :3000). Доменные сервисы
   наружу бизнес-логику не отдают — см. [01-architecture.md](01-architecture.md).
2. **Домены общаются по gRPC.** Контракты — в [`proto/`](../proto), правила
   вызова — в [02-grpc-model.md](02-grpc-model.md).
3. **Два слоя авторизации.** Клиент → gateway по JWT; gateway → домен по
   сервисному API-ключу. Детали — [02-grpc-model.md](02-grpc-model.md) §3.
4. **Проект — единица изоляции.** Всё, что относится к CRM, живёт внутри
   проекта; модули включаются per-project — [04-domain-model.md](04-domain-model.md).
5. **Роли — две независимые оси**, наследования между ними нет —
   [03-access-model.md](03-access-model.md).
